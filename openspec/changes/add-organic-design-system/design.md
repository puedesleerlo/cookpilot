## Context

The brief pins the palette (cream ground, tomato accent, sage, warm orange, charcoal) and
the shape language (irregular radii, blob shapes, paper grain, hand-drawn strokes). Those
are fixed. What is still open — typography, layout structure, the illustration idiom, and
where the design spends its one bold move — is where this document commits.

One honest risk to name up front: warm cream plus a terracotta accent is also the house
style of a great deal of generated design. The brief asks for it explicitly, so the
palette stands. The way out is not to fight the palette but to make the *structure*
specific: everything below is chosen to look like a kitchen, not like a template that
happens to be beige.

## Goals / Non-Goals

**Goals:**
- A token layer that makes it impossible for a screen to invent a colour or a spacing step.
- Typography with enough personality to carry the product's warmth, and enough clarity to
  be read across a kitchen with wet hands.
- An illustration set that does the work emoji would otherwise do badly.
- Timeline semantics decided here, not in the Gantt change.
- An accessibility floor that is structural, not a later audit.

**Non-Goals:**
- Screen layouts. Those belong to their own changes; this ships the parts they compose from.
- A theme switcher. One considered look, executed well.
- An icon font or a third-party icon set.

## Decisions

### The subject, stated plainly

The vernacular this design borrows from is not "recipe app". It is the **restaurant pass**:
the rail of tickets above the line, the masking-tape labels on deli containers, the
whiteboard with times on it, the scuffed steel of a working kitchen. That is where a
meal-prep session actually lives, and it is a far more specific well to draw from than
"food, but cosy".

Concretely, this shows up as:
- **Lane labels read as masking tape** — slightly rotated, torn-edge, hand-lettered feel —
  rather than as a table's row headers. This is the single most characteristic move in the
  interface and it appears exactly once, on the Gantt.
- **Dish colour is a strip down the left edge of every block**, the way a ticket rail is
  colour-coded, instead of tinting the whole block and fighting the text contrast.
- **Containers, not cards, for outputs.** The summary screen shows what you actually end
  up with: labelled tubs.

### Colour

| Token | Value | Job |
|---|---|---|
| `--c-cream` | `#FDF8F0` | The ground. Everything sits on it. |
| `--c-tomato` | `#E2553D` | Primary accent. Actions, the critical path, the compile moment. |
| `--c-sage` | `#7C9473` | Passive time, "this is working without you", success. |
| `--c-orange` | `#E8944A` | Heat, warnings, the second cook. |
| `--c-charcoal` | `#2E2A26` | Text. Never pure black — it would ring against cream. |

Derived, not invented: `--c-cream-deep` (`#F5EADB`) for recessed surfaces, `--c-ink-soft`
(`#6B625A`) for secondary text, `--c-line` (`#E0D3C0`) for hairlines, plus a four-step
tint ramp per accent generated by mixing toward cream.

**Dish hues** are a six-stop rotation — tomato, sage, orange, plum `#8C6A9B`, teal
`#4E8A8B`, mustard `#C9A227` — allocated from a stable hash of the dish id so the same
plan renders identically everywhere. Six is chosen because a session that produces more
than six dishes has a bigger problem than colour collision.

**Cook colours** come from a separate ramp (tomato, teal, plum, mustard) so a cook is never
confusable with a dish.

Contrast is checked as a test, not by eye: every documented pairing must clear 4.5:1 for
body and 3:1 for large text. Tomato on cream is 4.03:1 — **so tomato is never used for
body text**, only for large text, strokes and fills. The token file records that constraint
next to the token so it cannot be forgotten.

### Typography

One variable superfamily — **Recursive** — configured into three voices. This is the
design's central typographic idea, and it is specific to what the product actually is.

| Voice | Axes | Job |
|---|---|---|
| Display | `CASL 1`, `wght 800` | Screen titles, dish names, the compile moment. Casual axis at full tilt gives genuinely hand-drawn, rounded letterforms. |
| Interface | `CASL 0.3`, `wght 400–800` | Every label, button and body string. Timers use 800 with `tabular-nums`. |
| Compiler | `MONO 1`, `CASL 0`, `wght 500` | Compile status lines and the timeline's time ruler. Nothing else. |

The product's whole tension is *warm kitchen* against *compiler*, and Recursive spans
exactly that range on two axes of one typeface. Using one family for both voices is more
disciplined than pairing two unrelated faces, and it means the monospace is not the
generic "monospace for small data labels" tell — here the interface genuinely is a
compiler, and the mono voice is reserved for the places where it is speaking as one.

Scale (1.25, major third, from a 16px base): 12.8 / 16 / 20 / 25 / 31.25 / 39 / 48.8 / 61 / 76.
Body copy is capped at 68 characters. The font is self-hosted as a single variable woff2;
the app must survive offline.

**Rejected: Fraunces.** It was the obvious pick for "soft display face" and that is the
problem — it has become one of the reliable tells of generated design, and it is a serif
where the brief asked for something rounded. Recursive Casual is rounded, warmer, and
carries the second and third voices for free. Recorded as D-008.

### Layout

A single column on mobile; on desktop a 12-column grid with a 1200px measure and generous
gutters — except the Gantt, which breaks out to full bleed because it is the payoff.

```
DESKTOP — timeline screen                 MOBILE
+------------------------------------+   +----------------+
|  Compiled in 54 of 60 min   [chips]|   | 54 / 60 min    |
+------------------------------------+   +----------------+
| ~~~~~~~~ time ruler ~~~~~~~~~~~~~~ |   | ruler >>> scroll|
| [tape] Cook 1  ####  ///  ####     |   | [tape] Cook 1  |
| [tape] Cook 2   ##  ####   //      |   |  ####  ///     |
| [tape] Burner 1 ############       |   | [tape] Cook 2  |
| [tape] Pan       ####   ####       |   |  ##  ####      |
| [tape] Fridge         ////////     |   | (sticky labels)|
+------------------------------------+   +----------------+
| Why this order?   | Optimization   |   | Why this order?|
| - passive first   | 38 min saved   |   | ...            |
+------------------------------------+   +----------------+
```

Alignment is left throughout. Centred text is used in exactly one place — the compile
curtain — because that is the one moment the interface asks you to stop and look.

### Where the boldness is spent

On the Gantt, and nowhere else. The masking-tape lane labels, the full-bleed break-out and
the block treatment are the memorable thing. Every other screen is deliberately quiet:
plain cards, one accent, no decoration that is not carrying information.

### Motion

Three moments, total:
1. **Chips settle.** Ingredient chips arrive with a 240ms overshoot as they are recognised.
2. **Compile.** One orchestrated sequence — stage label crossfades while blocks slide in
   left-to-right in dependency order, so you watch the schedule assemble itself.
3. **Success.** A brief warm bloom behind the makespan figure. Not confetti; a pan flare.

Everything else — hovers, section reveals, card entrances — is static. Under
`prefers-reduced-motion` all three collapse to their end states with opacity only.

### Illustration idiom

Single-weight 2px strokes with deliberately imperfect paths (no path is symmetric), open
corners where two strokes meet, and one flat tint fill offset slightly from the outline —
the way a hand-drawn illustration is coloured slightly outside its own lines. Everything
uses `currentColor` for strokes so a glyph picks up its context.

Drawn as inline React components over a shared `<Glyph name>` registry rather than as
files, because they need to inherit colour and because a missing name must be a *type*
error, not a broken image.

## Risks / Trade-offs

- **The palette is close to a generated-design cliché.** Mitigated by spending the
  structure budget on the pass/ticket-rail idiom rather than on more warm blobs. If the
  result still reads generic, the lever is to push the tape, the containers and the hand
  strokes further — not to change the hex values, which the brief fixed.
- **Two variable fonts cost bandwidth.** ~140KB combined, subset to Latin, self-hosted and
  preloaded. Accepted: typography is carrying the personality, and the app is otherwise
  tiny and has no backend to wait on.
- **Hand-drawn SVG is slow to author and easy to do badly.** Thirty-odd drawings is real
  work. The alternative — emoji — is explicitly ruled out by the brief, and rightly:
  emoji would make the pantry review screen look like a chat message.
- **Hatched fills can moiré at small sizes.** The pattern is defined at a fixed user-space
  scale and the block minimum width is set so a `hold` block never renders narrower than
  the pattern's repeat.
